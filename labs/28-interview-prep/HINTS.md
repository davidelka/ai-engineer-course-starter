# רמזים למעבדה 28: Interview Prep

הקובץ הזה הוא למקרה שנתקעת. קודם נסה לבד לפי ה-docstring ב-`mine.py` ולפי הטסטים. אם נתקעת, קרא רק את **רמז 1** של הפונקציה, סגור את הקובץ ונסה שוב. רק אם עדיין תקוע, עבור ל**רמז 2**, ורק בסוף ל**רמז 3**, שמכיל את האלגוריתם המלא. כל רמה כתובה כך שאפשר לעצור אחריה.

את המימושים המלאים (reference) תמצא ב-`interviewkit/rubric.py`, `interviewkit/srs.py` ו-`interviewkit/aicoding.py`. כדאי לפתוח אותם רק אחרי שהטסטים שלך עוברים, כדי להשוות.

## term_in

### רמז 1: כיוון
הדרך הנוחה היא לבנות מכל מונח **ביטוי רגולרי** ולחפש אותו בטקסט המנורמל. `re.escape` מגן על תווים מיוחדים במונח. הכלים לגבולות הם lookbehind ו-lookahead שלילי (`(?<!...)`, `(?!...)`), ולא `\b`, כי `\b` של Python מחשיב אותיות עבריות כ"אותיות מילה" ואז תחילית כמו ו או ה תשבור את ההתאמה.

### רמז 2: מבנה
1. לנרמל את הטקסט ואת המונח (בלי ה-`*` בסוף, אם יש).
2. להחליט על גבול שמאלי: רק אם התו הראשון של המונח הוא אות לטינית או ספרה.
3. אם המונח הוא קידומת (`*`), לסיים כאן, בלי גבול ימני.
4. אחרת להוסיף סיומת רבים אופציונלית (רק אם המונח מסתיים באות לטינית) וגבול ימני (רק אם הוא מסתיים באות לטינית או ספרה).
5. `search` על הטקסט המנורמל.

### רמז 3: האלגוריתם המלא
- `prefix = term.endswith("*")`; `n = normalize(term.rstrip("*"))`.
- גבול שמאלי `(?<![a-z0-9])` אם `n[:1]` הוא ASCII ואלפאנומרי, אחרת כלום. (כך `"rag"` נמצא ב-`"RAG pipeline"` אבל לא ב-`"drag"`, ו-`"אמבדינג"` נמצא ב-`"והאמבדינג"`.)
- אם `prefix`: התבנית היא `left + re.escape(n)` (כך `"calibrat*"` נמצא ב-`"calibration"`).
- אחרת:
  - `plural = "(?:s|es)?"` אם `n[-1:]` הוא אות ASCII, אחרת כלום (`"embedding"` נמצא ב-`"embeddings"`).
  - גבול ימני `(?![a-z0-9])` אם `n[-1:]` הוא ASCII ואלפאנומרי, אחרת כלום (`"eval"` לא נמצא ב-`"evaluate"`; `"%"` נמצא ב-`"20%"` כי אין לו גבול).
  - התבנית היא `left + re.escape(n) + plural + right`.
- מחזירים `bool(re.compile(pattern).search(normalize(text)))`. (`normalize` כבר מוריד לאותיות קטנות, הופך `-`, `_` ו-`/` לרווח, ומכווץ רווחים.)

## score_answer

### רמז 1: כיוון
שני חלקים בלתי תלויים: **כיסוי** הרובריקה (משוקלל) ו**ארבע בדיקות מבנה**. `term_in` עושה את כל ההתאמות. המלכודת: קבוצה שנכתבה כמחרוזת בודדת ולא כרשימה, ו-`need` גדול ממספר הקבוצות.

### רמז 2: מבנה
1. בדיקת רובריקה ריקה או משקל כולל 0.
2. לכל נקודה: להפוך את הקבוצות לרשימות, למצוא לכל קבוצה את המונח הראשון שמתאים, לספור כמה קבוצות התאימו, ולהחליט אם הנקודה מכוסה.
3. לצבור את המשקל המכוסה, ולמלא `covered`, `missing` ו-`hits`.
4. ארבע הבדיקות המבניות.
5. חישוב הציון וחזרה עם המילון.

### רמז 3: האלגוריתם המלא
1. `rubric = question.get("rubric") or []`; `total = sum(p.get("weight", 1) for p in rubric)`; אם הרובריקה ריקה או `total <= 0`: `ValueError`.
2. לכל נקודה `p` בסדר הרובריקה:
   - `groups = [[g] if isinstance(g, str) else list(g) for g in p.get("concepts", [])]`.
   - לכל קבוצה: המונח הראשון בה ש-`term_in(answer, t)` מחזירה עבורו `True`, אם יש. רשימת המונחים האלה היא `matched`.
   - `need = min(p.get("need", 1), len(groups))`.
   - `hits[p["id"]] = matched` (המונח המתאים הראשון של כל קבוצה שהתאימה; ב-reference כל נקודה מקבלת רשומה, גם אם ריקה).
   - אם יש קבוצות ו-`len(matched) >= need`: ה-id נכנס ל-`covered` והמשקל (`p.get("weight", 1)`) נצבר. אחרת ה-id נכנס ל-`missing`.
3. בדיקות המבנה:
   - `length_ok`: `min_words <= len(answer.split()) <= max_words`;
   - `tradeoff`: מונח כלשהו מ-`TRADEOFF_TERMS` נמצא בתשובה;
   - `concrete`: יש בתשובה ספרה, או מונח מ-`CONCRETE_TERMS`;
   - `measurement`: יש בתשובה `"%"`, או מונח מ-`MEASURE_TERMS`.
4. `coverage = covered_weight / total`.
5. `score = round(100 * (0.75 * coverage + 0.25 * checks_passed / 4))` (עם ה-coverage הלא מעוגל).
6. מחזירים `{"score": score, "coverage": round(coverage, 3), "covered": [...], "missing": [...], "hits": {...}, "checks": {...}, "words": len(answer.split())}`.

## sm2_review

### רמז 1: כיוון
SM-2 הוא האלגוריתם הקלאסי של SuperMemo לחזרה מרווחת. יש שני מסלולים (הצלחה וכישלון) שמשנים את המרווח, ועדכון של ה-ease factor שקורה תמיד. המלכודת: לחשב את המרווח החדש עם ה-ef **הישן**, ולא לשנות את מילון הקלט.

### רמז 2: מבנה
1. בדיקת `grade` (כולל דחיית `bool`, שהוא תת-מחלקה של `int` ב-Python).
2. העתקה של ה-state (או מילון ריק לכרטיס חדש) וקריאת הערכים עם ברירות מחדל.
3. ענף הצלחה וענף כישלון לחישוב המרווח, `reps` ו-`lapses`.
4. עדכון ef, חסימה מלמטה ועיגול.
5. חישוב `due` ו-`last` ועדכון ההעתק.

### רמז 3: האלגוריתם המלא
1. אם `grade` הוא `bool`, או לא `int`, או מחוץ ל-0..5: `ValueError`.
2. `new = dict(state or {})` (שאר המפתחות נשמרים כמו שהם). ערכי התחלה: `ef = 2.5`, `reps = 0`, `interval = 0`, `lapses = 0`.
3. אם `grade >= 3`: `interval = 1` אם `reps == 0`; `6` אם `reps == 1`; אחרת `math.ceil(round(interval * ef, 6))`: מעגלים כלפי מעלה, כמו בתיאור המקורי של SM-2 (ה-`round` הפנימי רק מנקה רעש של float), עם ה-ef הישן. אחר כך `reps += 1`.
4. אם `grade < 3`: `reps = 0`, `interval = 1`, `lapses += 1`.
5. תמיד, אחרי המרווח: `ef = ef + (0.1 - (5 - grade) * (0.08 + (5 - grade) * 0.02))`, אחר כך `ef = max(1.3, ef)`, ועיגול ל-4 ספרות.
6. `due = (today + timedelta(days=interval)).isoformat()`, `last = today.isoformat()`.
7. מעדכנים ב-`new` את `ef`, `reps`, `interval`, `lapses`, `due`, `last` ומחזירים אותו.

## grade_from_score

### רמז 1: כיוון
מיפוי של טווחים לציונים. המלכודת: סדר הבדיקות; אם תבדוק `>= 20` לפני `>= 90`, הכול יקבל 1.

### רמז 2: מבנה
לולאה על זוגות של (סף, ציון) מהגבוה לנמוך, החזרה בסף הראשון שעוברים, ו-0 בסוף.

### רמז 3: האלגוריתם המלא
`>= 90` נותן 5, `>= 75` נותן 4, `>= 60` נותן 3, `>= 40` נותן 2, `>= 20` נותן 1, אחרת 0.

## pick_session

### רמז 1: כיוון
שתי רשימות שמחוברות ונחתכות: חזרות שהגיע זמנן, ואז כרטיסים חדשים. מפתח מיון שהוא tuple נותן מיון לפי כמה קריטריונים בבת אחת. המלכודת: states של מזהים שלא בבנק צריך להתעלם מהם, ו-`bank_ids` יכול להיות generator שאפשר לעבור עליו רק פעם אחת.

### רמז 2: מבנה
1. להפוך את `bank_ids` לרשימה.
2. רשימת החזרות: מזהים שיש להם state ותאריך ה-due שלהם לא אחרי היום, ממוינים.
3. רשימת החדשים: מזהים בלי state, בסדר הבנק, חתוכה.
4. חיבור וחיתוך ל-`limit`.

### רמז 3: האלגוריתם המלא
1. `ids = list(bank_ids)`.
2. `due = [i for i in ids if i in states and date.fromisoformat(states[i]["due"]) <= today]`, ממוינים לפי `(states[i]["due"], states[i].get("ef", 2.5), i)`: הכי באיחור קודם, ובין שווים הכרטיס הקשה יותר (ef נמוך) קודם.
3. `new = [i for i in ids if i not in states][:max(0, new_per_day)]`.
4. מחזירים `(due + new)[:max(0, limit)]`.

## top_k_cosine

### רמז 1: כיוון
Cosine similarity היא מכפלה סקלרית חלקי מכפלת הנורמות. עם numpy מחשבים את כל השורות בבת אחת: `matrix @ query` ו-`np.linalg.norm(matrix, axis=1)`. המלכודת: חלוקה באפס לווקטור אפס (תיתן NaN ואזהרה), ומיון שלא שומר על סדר האינדקסים בשוויון.

### רמז 2: מבנה
1. המרה ל-`np.asarray(..., dtype=float)` ובדיקות צורה.
2. החזרת רשימה ריקה ל-`k <= 0` או מטריצה ריקה.
3. חישוב הנורמות, מערך דמיון של אפסים, ומילוי רק במקומות שבהם המכנה חיובי (מסכה בוליאנית).
4. מיון יציב בסדר יורד, חיתוך ל-k, והמרה ל-`int` ו-`float` של Python.

### רמז 3: האלגוריתם המלא
1. אם `query.ndim != 1` או `matrix.ndim != 2` או `matrix.shape[1] != query.shape[0]`: `ValueError`.
2. אם `k <= 0` או `matrix.shape[0] == 0`: `[]`.
3. `qn = np.linalg.norm(query)`; `rn = np.linalg.norm(matrix, axis=1)`; `denom = rn * qn`.
4. `sims = np.zeros(n)`; `ok = denom > 0`; `sims[ok] = (matrix[ok] @ query) / denom[ok]`. (שורה או שאילתה של אפסים מקבלות 0.0, בלי NaN ובלי אזהרה.)
5. `order = np.argsort(-sims, kind="stable")[:k]` (המיון היציב שומר את האינדקס הנמוך קודם בשוויון; `k > n` פשוט נותן את כל השורות).
6. מחזירים `[(int(i), float(sims[i])) for i in order]`.

## fit_to_budget

### רמז 1: כיוון
מפרידים בין הודעות system לשאר. ההודעה האחרונה תמיד נשמרת, ומשם הולכים **אחורה** בזמן ומוסיפים כל עוד יש מקום. המלכודת: לדלג על הודעה גדולה כדי להכניס הודעה ישנה יותר; ההיסטוריה שנשמרת חייבת להיות רצופה.

### רמז 2: מבנה
1. פונקציית עלות להודעה.
2. שתי רשימות: system ושאר ההודעות. בדיקות שגיאה.
3. חישוב העלות של כל ה-system ועוד ההודעה האחרונה, ובדיקה מול התקציב.
4. לולאה הפוכה על ההודעות הקודמות, עם `break` בראשונה שלא נכנסת.
5. היפוך הרשימה חזרה לסדר כרונולוגי, הסרת הודעת assistant בהתחלה אם צריך, והחזרת עותקים.

### רמז 3: האלגוריתם המלא
1. `cost(m) = count(m["content"]) + MESSAGE_OVERHEAD`.
2. `systems` = ההודעות עם `role == "system"`; `rest` = כל השאר. אם `rest` ריקה: `ValueError`.
3. `used = sum(cost(m) for m in systems) + cost(rest[-1])`. אם `used > budget`: `ValueError`.
4. `kept = [rest[-1]]`. עוברים על `rest[:-1]` מהסוף להתחלה: אם `used + cost(m) > budget`, עוצרים (`break`); אחרת מוסיפים ל-`kept` ומגדילים את `used`.
5. הופכים את `kept` לסדר המקורי.
6. אם `len(kept) > 1` וההודעה הראשונה ב-`kept` היא של `assistant`: מסירים אותה, כדי שהשיחה תתחיל ממשתמש.
7. מחזירים `[dict(m) for m in systems] + [dict(m) for m in kept]` (עותקים; הקלט לא משתנה).
