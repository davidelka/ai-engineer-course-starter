## normalize_field

### רמז 1: כיוון

המטרה היא שהבדלי פורמט ("₪ 1,345.40" מול 1345.4) לא ייספרו כשגיאת חילוץ. כתוב קודם את "חוק הטקסט", כי כל שאר הסוגים נופלים אליו כשהפירוש נכשל. לתאריכים, `datetime.strptime` עם רשימת פורמטים עושה את רוב העבודה וגם דוחה תאריך בלתי אפשרי. המלכודת: `bool` הוא תת-מחלקה של `int` ב-Python, ולכן צריך לבדוק אותו לפני שבודקים מספרים.

### רמז 2: מבנה

פונקציית עזר לחוק הטקסט. אחר כך בדיקת None בהתחלה, ואז ענף לכל kind. ב-money וב-int: קודם bool (מחזירים כמו שהוא), אחר כך מספר, ואחר כך מחרוזת שמנקים ומנסים להמיר בתוך try; כישלון הולך לחוק הטקסט. ב-date: לולאה על רשימת פורמטים, הראשון שמצליח מנצח; אם אף אחד לא, חוק הטקסט. ב-list: חוק הטקסט על כל פריט, ואז מיון.

### רמז 3: האלגוריתם המלא

- **"money"**: None נשאר None. int/float (לא bool): `round(float(v), 2)`. מחרוזת: מסירים את סימני המטבע `₪ $ € £` ואת המילים `NIS ILS USD EUR GBP` (בכל רישיות), מסירים רווחים ופסיקים (פסיק הוא מפריד אלפים), ואז `round(float(...), 2)`. `"₪ 1,345.40"` נותן 1345.4, `"NIS 52.69"` נותן 52.69. אם `float()` עדיין נכשל: חוק הטקסט.
- **"date"**: None נשאר None. מחזירים `"yyyy-mm-dd"` עבור `"2026-10-14"`, `"14/10/2026"`, `"14.10.2026"`, `"14-10-2026"` (**היום קודם**, כמו בקבלות בישראל), `"Oct 14, 2026"`, `"October 14 2026"`, `"14 Oct 2026"`. (פורמטים מתאימים ל-strptime: `%Y-%m-%d`, `%d/%m/%Y`, `%d.%m.%Y`, `%d-%m-%Y`, `%b %d, %Y`, `%B %d %Y`, `%d %b %Y`, ואפשר להוסיף וריאציות.) תאריך בלתי אפשרי (`"2026-14-10"`) או כל מחרוזת אחרת: חוק הטקסט.
- **"int"**: None נשאר None; `int(round(float(str(v).replace(",", ""))))`; בכישלון, חוק הטקסט.
- **"code"**: None נשאר None; `str(v).strip()` (רישיות חשובה: `"SPW-4013" != "spw-4013"`).
- **"list"**: None נשאר None; רשימה ממוינת של חוק הטקסט על כל פריט (כך שסדר ורישיות לא משנים).
- **"text"** (וזה גם "חוק הטקסט"): None נשאר None; מכווצים whitespace לרווח אחד, `casefold()`, ואז מסירים מהקצוות את התווים: רווח `. , : ; ! ? " '`.
- ערכי bool מוחזרים ללא שינוי ב-money וב-int.

## field_accuracy

### רמז 1: כיוון

כל העבודה הקשה כבר נמצאת ב-`normalize_field`. כאן רק עוברים על השדות לפי הסדר ב-`kinds`. המלכודות: pred יכול להיות מודל Pydantic (יש לו `model_dump()`), ו-mismatches שומרים את הערכים **המקוריים**, לא המנורמלים.

### רמז 2: מבנה

הפוך את pred למילון אם הוא מודל. צור `FieldReport` ריק. לולאה על `kinds.items()`: קח את הערך מה-gold ומה-pred, השווה אחרי נרמול, רשום ב-`correct`, ואם לא נכון הוסף ל-`mismatches`. החזר את הדוח.

### רמז 3: האלגוריתם המלא

1. אם pred הוא מודל Pydantic, `pred = pred.model_dump()`.
2. לכל `(name, kind)` ב-`kinds`, לפי הסדר:
   - `g = gold.get(name)`; `p = None if pred is None else pred.get(name)`;
   - `ok = pred is not None and normalize_field(p, kind) == normalize_field(g, kind)`;
   - `report.correct[name] = ok`;
   - אם לא ok: `report.mismatches.append((name, p, g))` (הערכים המקוריים).
3. מחזירים את ה-`FieldReport`; התכונה `.accuracy` שלו היא החלק של השדות הנכונים.

## image_tokens

### רמז 1: כיוון

אלה כללים שפורסמו על ידי הספקים, לא משהו שגוזרים לבד. ההבדל העיקרי בין הספקים הוא יחידת המדידה: Anthropic סופרת ריבועים של 28 פיקסלים, OpenAI סופרת patches של 32 או tiles של 512, ו-Gemini 3 בכלל לא מסתכלת על הגודל. המלכודת: הקטנת התמונה היא לולאה (מקטינים עד שנכנסים בתקציב), והעיגולים (`int`, `round`, `ceil`, `//`) צריכים להיות בדיוק כמו בייחוס, כי הטסט משווה מול הייחוס על הרבה גדלים.

### רמז 2: מבנה

פונקציה ראשית שמפנה לפי provider ושם המודל לפונקציית עזר לכל כלל. ל-Anthropic: חילוץ גרסה מהשם עם regex (שני מספרים אחרי שם המשפחה), בחירת tier, ואז לולאת הקטנה על הצלע הארוכה בצעדים של 28. ל-OpenAI patches: התאמה ל-max_dim, ספירת patches, ואם חורגים, לולאה שמקטינה את קנה המידה ב-1% כל פעם. ל-gpt-4o: התאמה, הקטנת הצלע הקצרה ל-768, ספירת tiles. ל-Gemini: טבלה קבועה (3 ומעלה) או חישוב crop (2). כל מקרה אחר: `ValueError`.

### רמז 3: האלגוריתם המלא

**anthropic** (כל מודל):

1. tier = `"high"` כשגרסת המודל היא 4.7 ומעלה (`"claude-haiku-5-5"` נותן `(5, 5) >= (4, 7)`) או כשאין לשם גרסה (למשל `"mock-model"`); אחרת `"standard"` (`"claude-haiku-4-5"`).
2. מגבלות: high = צלע ארוכה 2576 px ו-4784 tokens; standard = 1568 px ו-1568 tokens.
3. `tokens(w, h) = ceil(w/28) * ceil(h/28)`.
4. אם הצלע הארוכה `<= limit` **וגם** `tokens(w, h) <= token limit`, משאירים `(w, h)`.
5. אחרת `new_long = (min(long, limit) // 28) * 28`, וחוזרים על:
   - `new_short = max(1, round(short * new_long / long))`;
   - עוצרים אם `tokens(new_long, new_short) <= token limit` (או `new_long <= 28`);
   - אחרת `new_long -= 28`.
6. מחזירים את ה-tokens של התמונה המוקטנת (שומרים על הכיוון: portrait נשאר portrait).

**openai, מודלי patches**: מודל שמתחיל ב-`"gpt-5.4"` (gpt-5.4, gpt-5.4-mini, gpt-5.4-nano). detail `"auto"` פירושו `"high"`. `(max_dim, budget)`: low = `(2048, 6144)`, high = `(2048, 2500)`, original = `(6000, 10000)`.

1. fit: `s = min(1, max_dim / w, max_dim / h)`; אם `s < 1`: `w, h = int(w * s), int(h * s)`.
2. `patches = ceil(w/32) * ceil(h/32)`.
3. אם `patches > budget`: `s = sqrt(budget * 32 * 32 / (w * h))`; בלולאה: `nw, nh = int(w * s), int(h * s)`; אם `ceil(nw/32) * ceil(nh/32) <= budget`, יוצאים; אחרת `s *= 0.99`. ואז `patches = ceil(nw/32) * ceil(nh/32)`.
4. `tokens = ceil(patches * 1.2)`.

**openai, מודל tiles `"gpt-4o"`**: detail `"low"` נותן 85. אחרת מתאימים לתוך 2048 x 2048 (כמו בצעד 1); אם `min(w, h) > 768`: `s = 768 / min(w, h)`; `w, h = int(w * s), int(h * s)`; `tokens = 85 + 170 * ceil(w/512) * ceil(h/512)`.

**gemini, מודל `"gemini-3..."` ומעלה**: detail (media resolution) low 280, medium 560, high 1120, ultra_high 2240; None או כל דבר אחר נותן 1120. הגודל לא משנה.

**gemini, מודל `"gemini-2..."`**: 258 אם `w <= 384` וגם `h <= 384`. אחרת `crop = max(256, min(768, floor(min(w, h) / 1.5)))`; `tokens = 258 * ceil(w/crop) * ceil(h/crop)`.

**כל דבר אחר**: `ValueError`.

## normalize_hebrew

### רמז 1: כיוון

`unicodedata` הוא הכלי: `normalize("NFC", ...)` ו-`category(ch)`. עיקר העבודה הוא סדרה של החלפות, ו**הסדר** חשוב: למשל, את הגרש בתוך מילה צריך למחוק **לפני** שהופכים כל שאר הפיסוק לרווח, אחרת "צה"ל" יהפוך לשתי מילים.

### רמז 2: מבנה

שבעה צעדים קטנים זה אחרי זה, כל אחד שורה או שתיים: NFC; מחיקת סימני כיוון (regex עם מחלקת תווים); מחיקת ניקוד וטעמים (regex); מקף עברי ומקף רגיל לרווח; מחיקת גרש וגרשיים בין שני תווי מילה (regex עם lookbehind ו-lookahead), ואחר כך כל תו פיסוק לרווח; אותיות סופיות (`str.maketrans`); אותיות קטנות וכיווץ רווחים.

### רמז 3: האלגוריתם המלא

בסדר הזה:

1. `unicodedata.normalize("NFC", text)`.
2. מוחקים את סימני הכיוון הבלתי נראים U+200E, U+200F, U+202A..U+202E, U+2066..U+2069.
3. מוחקים ניקוד וטעמים: U+0591..U+05BD, U+05BF, U+05C1, U+05C2, U+05C4, U+05C5, U+05C7.
4. מחליפים מקף עברי (U+05BE) ו-`"-"` ברווח (`"בית־ספר"` נותן `"בית ספר"`).
5. מוחקים גרש U+05F3, גרשיים U+05F4, `'` ו-`"` כשהם יושבים **בין** שני תווי מילה (`\w` משני הצדדים, למשל `(?<=\w)[׳״'"](?=\w)`): `'צה"ל'` נותן `"צהל"`, `"ג'ירפה"` נותן `"גירפה"`. אחר כך כל תו שנשאר שה-`unicodedata.category` שלו מתחיל ב-`"P"` הופך לרווח.
6. אם `finals`: ך→כ, ם→מ, ן→נ, ף→פ, ץ→צ.
7. אותיות קטנות, וכיווץ כל ה-whitespace לרווח אחד (עם strip בקצוות).

`"שָׁלוֹם, עוֹלָם!"` נותן `"שלומ עולמ"`. ספרות נשארות כמו שהן.

## wer

### רמז 1: כיוון

זה Levenshtein רגיל, רק על מילים במקום על תווים. צריך טבלת תכנות דינמי, ואז הליכה אחורה בטבלה כדי לשחזר את רשימת הפעולות. המלכודת: כשיש כמה מסלולים זולים באותה מידה, הטסטים מצפים לסדר העדפה מסוים, ובסוף צריך להפוך את הרשימה לסדר קריאה.

### רמז 2: מבנה

נרמול (אם יש), פיצול למילים, טיפול ב-reference ריק. בניית טבלה בגודל `(n+1) x (m+1)` עם שורה ועמודה ראשונות של 0, 1, 2, ... הליכה אחורה מהפינה `(n, m)` עם לולאת while: בכל צעד בודקים קודם את האלכסון, אחר כך מחיקה, אחר כך הוספה, ובוחרים את הראשון שעקבי עם הטבלה. ספירת S, D, I מתוך הפעולות, היפוך הרשימה, ובניית `ErrorRate`.

### רמז 3: האלגוריתם המלא

1. אם `normalize` אינו None, מפעילים אותו על שני הטקסטים. מפצלים לפי whitespace: `ref` באורך n, `hyp` באורך m.
2. reference ריק: rate 0.0 אם גם ה-hypothesis ריק, אחרת 1.0.
3. ממלאים טבלת edit distance בגודל `(n+1) x (m+1)`: `d[i][0] = i`, `d[0][j] = j`, ו-`d[i][j] = min(d[i-1][j-1] + (0 if ref[i-1] == hyp[j-1] else 1), d[i-1][j] + 1, d[i][j-1] + 1)` (החלפה, מחיקה והוספה עולות 1 כל אחת).
4. הולכים אחורה מ-`(n, m)` ובונים את ops, ובמקרה של שוויון מעדיפים בסדר הזה:
   - אלכסון: `("ok", w, w)` אם המילים שוות, אחרת `("sub", ref_word, hyp_word)`;
   - אחר כך `"del"` (מילה של ה-reference שחסרה ב-hypothesis): `("del", ref_word, "")`;
   - אחר כך `"ins"`: `("ins", "", hyp_word)`.
   (צעד הוא חוקי כשהערך בתא הנוכחי שווה לערך בתא הקודם ועוד העלות של הצעד, ו-i או j בגבולות.)
5. הופכים את ops לסדר קריאה.
6. מחזירים `ErrorRate(rate, substitutions, deletions, insertions, ref_len, hyp_len, ops)` עם `rate = (S + D + I) / ref_len`. ה-rate יכול לעבור את 1.0.
